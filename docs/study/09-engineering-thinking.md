# 09 Agent 工程思维

## 本章目标

学完本章，你应该能：

- 总结 Agent 工程中的常见设计取舍。
- 理解可观测性、降级、测试、配置和依赖服务的重要性。
- 解释 Jarvis 为什么需要 Qdrant、PostgreSQL、LLM API 和搜索 API。
- 用工程视角评估一个 Agent 功能是否值得做。

## 核心概念

Agent 工程不是把 LLM 接进项目就结束。真正困难的是把不稳定、昂贵、慢速、外部依赖很多的模型能力，包装成可维护的后端系统。

Jarvis 体现了几个重要工程思维：

- 边界清晰：API、Graph、Node、Tools、Memory、LLM Provider 各司其职。
- 配置外置：端口、模型、阈值、数据库地址和 API key 都来自环境变量。
- 可降级：PostgreSQL 或 Qdrant 不可用时，对话尽量继续。
- 可扩展：新增工具和模型厂商有明确扩展点。
- 可测试：unit、integration、e2e 分层测试。
- 成本可控：Reflection 有最大重试次数，工具和模型调用有明确位置。
- 缓存意识：稳定 prompt、RAG 检索、工具结果和 embedding 可以复用，但要控制权限、时效性和一致性。

Agent 系统的核心问题经常不是“模型能不能做到”，而是：

- 做不到时系统怎么办？
- 做错时谁发现？
- 外部依赖慢了怎么办？
- 成本超了怎么办？
- 用户需要删除记忆时怎么办？
- 新模型上线时怎么切换？

## 关键设计问题

为什么 Jarvis 需要 Qdrant？

因为长期知识需要语义检索。普通数据库适合按字段查，向量数据库适合按意思查。RAG 场景下，用户问题和文档内容不一定共享关键词，但语义可能相关。

为什么 Jarvis 需要 PostgreSQL？

对话历史是结构化、按用户和时间组织的数据。关系数据库能可靠保存、查询和删除这些记录。

为什么 Jarvis 需要搜索 API？

模型训练数据不是实时数据库。在线搜索让 Agent 能获取较新的外部信息。但搜索也带来延迟、费用和可靠性问题，所以它被封装成工具，而不是每次请求默认执行。

为什么需要分层测试？

Agent 系统依赖很多外部组件。如果只做端到端测试，失败时很难定位。单元测试验证局部逻辑，集成测试验证存储和 graph，E2E 测试验证 API 行为。

为什么降级策略重要？

Agent 依赖模型、数据库、向量库、搜索 API、网页。任何一个组件都可能失败。合理降级能保证系统在能力下降时仍然可用，而不是全盘失败。

大模型服务里的缓存命中指什么？

它通常不是单一概念，而是分层发生：

- 推理引擎内部的 KV Cache：复用已经计算过的 attention key/value，减少重复上下文计算。
- 服务层的 Prompt / Prefix Cache：复用相同 system prompt、工具 schema、业务规则等稳定前缀的预填充结果。
- 应用层缓存：复用 embedding、RAG 检索结果、工具调用结果或 FAQ 类最终回答。

命中率高通常意味着平均延迟更低、GPU 计算浪费更少、吞吐更好、单位请求成本更低。命中率低则说明大量请求都在重新计算 prompt、重新检索或重新调用外部服务，成本和延迟都会上升。

但命中率不是越高越好。Agent 请求经常包含用户身份、权限、历史对话、实时工具结果和 RAG 上下文。如果缓存 key 设计粗糙，可能把 A 用户的数据复用给 B 用户，或者把过期工具结果当成事实。工程上要同时看命中率、过期策略、权限隔离、缓存污染和答案正确性。

在 Jarvis 里可以优先考虑这些缓存点：

- 固定 system prompt 和工具 schema：适合服务层 prefix cache。
- 文档 embedding：同一 chunk 不应重复向量化。
- RAG top-k 结果：可以对公共知识库做短 TTL 缓存，但用户私有知识必须按 `user_id` 隔离。
- 搜索和网页抓取结果：可以短 TTL 缓存，避免每次 Agent 都打外部 API。
- 完整 LLM 回答：只适合 FAQ 或确定性强、权限一致的场景，不适合开放式个性化对话。

1. Jarvis 中哪些依赖是外部服务？
2. 哪些配置会影响成本？
3. 哪些配置会影响答案质量？
4. 为什么 Agent 循环必须有上限？
5. 你会如何给 Jarvis 增加可观测性？
6. 大模型服务中的 KV Cache、Prompt Cache 和业务层缓存分别缓存的是什么？
7. 为什么缓存命中率高不一定代表系统一定正确？

## 小练习

做一次 Agent 功能评审。假设有人提议：“每次用户提问前，都自动搜索 Web，再自动抓取前三个网页，再让模型回答。”

不用写代码，只回答：

- 这个方案质量上有什么好处？
- 成本和延迟有什么问题？
- 错误面会增加在哪里？
- 有没有更稳的触发条件？
- 你会如何把这个能力放进 Jarvis 现有架构？
