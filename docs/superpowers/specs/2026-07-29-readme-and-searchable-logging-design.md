# README 与可检索关键日志设计

## 背景

Jarvis 当前 README 已覆盖架构、快速开始、API、LLM 配置、自定义 Agent、
降级策略和测试，但没有系统说明最近新增的彩色日志、模型启动连通性检查和专用
健康端点。现有应用日志也主要依赖英文自然语言，供应商、模型、工作节点和组件
等定位字段不够醒目，人工浏览和文本检索效率较低。

## 目标

1. 为关键运行日志增加统一、醒目且可检索的 `【类别:值】` 标签。
2. 保持当前 INFO、WARN、ERROR 的绿色、黄色、红色等级渲染。
3. 避免为了可观测性记录所有节点进入与退出，控制生产日志量。
4. 更新 README，使项目使用者和运维人员能准确理解启动、模型检查、日志和健康
   探针行为。
5. 保持日志脱敏，不记录 API Key、完整用户输入、完整模型响应或可能包含凭据的
   异常详情。

## 非目标

- 不在本次增加全链路 request ID 或分布式追踪。
- 不为每个 LangGraph 节点打印进入和退出日志。
- 不改变 HTTP/gRPC 接口、模型选择、重试、降级或健康检查语义。
- 不改变 Uvicorn 普通访问日志；现有健康探针访问日志过滤继续生效。

## 日志格式

关键日志统一使用：

```text
【类别:值】【类别:值】 English event description
```

标签使用稳定的中文类别名，值保持代码和配置中的原始标识，方便视觉识别和精确
检索。例如：

```text
【供应商:deepseek】【模型:deepseek-v4-pro】【类型:Chat】【结果:成功】 Startup connectivity check completed
【节点:rag_retrieve】【组件:Qdrant】【状态:降级】 Retrieval unavailable, skipping RAG
【节点:agent_dispatch】【Agent:ai-agent-mentor】【评分:0.86】 Agent selected
```

多个标签之间不添加空格，标签组与英文事件正文之间保留一个空格。

## 标签覆盖范围

### 模型启动检查

- Chat：`供应商`、`模型`、`类型:Chat`、`结果`
- Embedding：`供应商`、`模型`、`类型:Embedding`、`结果`
- 失败时增加脱敏的 `类别`，例如 `credential`、`timeout` 或
  `connectivity`
- 配置尚未解析、无法确定供应商或模型时使用稳定占位值 `unknown`

启动检查仍只探测 `profiles` 实际引用的 Chat 供应商，并检查当前
`EMBED_MODEL` 指定的 Embedding 模型。

### LangGraph 关键决策

- Agent 匹配成功：`节点:agent_dispatch`、`Agent`、`评分`
- Agent 低于阈值或失败降级：`节点:agent_dispatch`、`状态`
- 反思结果无法解析或触发重试：`节点:reflect`、`状态`，可安全输出评分与重试
  次数时再添加对应标签
- 不打印每个节点的正常进入和退出

### 存储、工具和服务生命周期

- PostgreSQL、Qdrant 初始化和运行期降级：`组件`，节点内事件增加 `节点`
- 工具或 Agent 定义解析失败：使用 `工具`、`Agent` 或 `组件` 标签
- HTTP/gRPC 监听：`服务`、`端口`、`状态`
- 未能安全归类的内部异常只输出稳定类别，不输出凭据或完整请求内容

## 实现方式

在 `jarvis/logging_config.py` 提供一个小型标签格式化函数，接收稳定的键值字段并
返回连续的 `【类别:值】` 字符串。业务模块通过该函数构造关键日志前缀，避免每个
模块手写括号格式产生差异。

格式化函数应：

- 保持字段传入顺序；
- 将值转换为字符串；
- 清理换行和闭合方括号等会破坏单行标签边界的字符；
- 不负责判断字段是否敏感，调用方只能传入已批准的稳定标识；
- 不改变日志等级颜色格式化器和健康访问日志过滤器。

现有关键日志逐点迁移，不批量改写所有日志。新增或修改的行为由单元测试验证标签
顺序、特殊字符处理以及代表性的启动、节点、存储和服务日志。
